# ホスト詳細設計

## 責務

| 機能 | 処理 |
| --- | --- |
| 端末管理 | 端末設定、Appiumセッション、疎通、画面情報を管理する。 |
| 操作・記録 | ブラウザ入力を検証し、端末操作層へ渡す。成功した操作を記録下書きへ反映する。 |
| 実行スケジューラ | 実行対象、シナリオ版、端末ごとの進捗、キャンセル、同時実行数を管理する。 |
| 画像処理 | 画像の取得・保存・照合を行い、実行器へ判定結果を返す。 |
| 配信 | ブラウザに端末一覧、映像、実行イベントを配信する。 |

## 排他と再試行

- 1端末につきAppiumセッション1つと、操作権1つを使用する。操作権の所有者は手動クライアントまたは実行タスク。状態・映像の閲覧は操作権なしで行える。
- 手動操作権はブラウザが更新し、切断や期限切れで解放する。処理中の入力が確定するまでは新しい所有者に操作させない。
- 端末へ向かう変更コマンドを直列化する。映像は別経路で中継し、撮影・照合にはホスト全体の並行数制限を適用する。
- シナリオ実行前に端末の操作権を取得する。占有中や非対応の端末には、その理由を示して実行を開始しない。端末ごとの失敗で他端末の処理をキャンセルしない。
- シナリオの実行待ちは永続化する。上限に達した場合は待機列で待つ。先に待ち始めた実行から、空いている端末に割り当てる。
- スクリーンショットや接続状態などの読み取りは、期限内に再試行できる。実機に送信したタップ・長押し・スワイプは、結果が不明なら再送しない。

## 状態と復旧

端末の接続状態は `disconnected`、`connecting`、`ready`、`error` で扱う。操作中の表示は接続状態と操作権から決める。通信異常からの接続回復時は、必要に応じてAppiumセッションを作り直し、画面の向き・寸法を取り直す。

端末別実行は `queued`、`running`、`waiting_for_image`、`succeeded`、`failed`、`cancelled`、`interrupted` を持つ。中断要求は進行中の通信を打ち切ったように見せず、次の操作送信を止める。送信済み操作の成否が不明なら `interrupted` とし、理由を記録する。

操作送信前に、その操作と送信予定状態を永続化する。送信完了時に結果を更新し、記録セッションなら下書きステップ追加も同一トランザクションで行う。プロセス再起動時は処理中だった実行と送信予定のまま残った操作を `interrupted` とする。待機中でまだ実機に送信していない実行のみ、対象を再検査して開始できる。

## 永続化

| データ | 主な内容 |
| --- | --- |
| 端末・接続先 | 内部ID、UDID、名前、iOS版、Appium URL参照、映像接続設定 |
| シナリオ・版 | ステップ、設定、画像参照。実行時は保存済みの不変版を使用 |
| 記録下書き | 記録元端末、成立したジェスチャーと間隔、最終保存時刻 |
| 画像素材 | 画像ID、ハッシュ、画像寸法、ローカル保管先 |
| 実行・端末別実行 | 対象の版と端末、状態、開始・終了、現在ステップ |
| イベント | 操作ID、結果、経過時間、分岐、照合スコア、診断画像参照 |

起動時にスキーマを検査し、必要に応じてバージョン付きの移行を行う。画像は一時ファイルへ書き出してから確定し、完全なファイルのみDBで参照する。実行ログには端末と操作を突き合わせられるIDを付け、トークンや認証情報は記録しない。
