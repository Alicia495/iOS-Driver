# シナリオ実行設計

## データモデル

シナリオは名前、説明、形式バージョン、開始ステップID、ステップ一覧、画像条件一覧を持つ。保存ごとに変更できないシナリオ版を発行する。同じ実行内の全端末が同じ版と画像素材を参照する。編集画面の順序は表示順を表し、実行順はステップIDの遷移で決める。並べ替え時は通常の次ステップを更新し、明示した分岐先はIDで保持する。

| 種類 | 設定と結果 |
| --- | --- |
| `gesture` | タップ、長押し、スワイプ。正規化点と画面プロファイルを指定し、成功時に次へ進む。 |
| `delay` | 指定ミリ秒だけ待って次へ進む。停止要求で待機を解除する。 |
| `wait_image` | 指定条件の一致を最大時間まで待つ。一致時と期限切れの遷移を指定できる。 |
| `branch_image` | 1枚の画像に複数条件を適用し、一致した最優先の分岐先へ進む。期限まで再評価できる。一致なしの分岐先も設定できる。 |
| `tap_image` | 指定画像を現在画面から探して一意に特定できた位置をタップする。既定のタップ位置は矩形中心。 |
| `end` | 成功または明示的な失敗として終了する。 |

画像条件は、素材ID、照合閾値、任意の探索矩形、対象の向き、必要に応じて機種・表示バリエーションを持つ。各タイムアウトの遷移を省略した場合は、その端末を失敗で停止する。画像取得エラーは条件不一致と区別する。

## 記録と再生

- 操作権を取得して記録を開始する。ホストに届いたジェスチャーを直ちに実機へ送り、成功が確認できた操作を下書きに追加する。タップが送信できなかった場合や、送信後に結果不明になった場合は記録一覧とは別に結果を表示する。
- 操作間隔は、前操作の完了から次操作の受付までをホストの単調時計で計測する。保存時に編集可能な待機ステップに変換する。最初の操作前には既定で待機を挿入しない。実行時も各操作の完了から待機を数える。
- 再生は端末ごとに開始ステップから実行する。開始前にシナリオ版、画像素材、端末の接続と対応画面プロファイルを検査する。実行途中で向きや画面条件が合わなくなった場合は、そのステップを失敗として扱う。
- 一定の待機だけでは端末ごとの読込時間差を吸収できない箇所に、画像条件を入れる。条件は操作後に新たに撮影した画面で判定する。

## 終了と検証

初版では遷移の循環、存在しない分岐先、到達できないステップ、存在しない画像、矛盾する閾値や探索矩形を保存時に検出する。明示的な終了ノードを置く。期限、フレーム取得回数、操作数に上限を持たせる。分岐の優先順位は画面上で編集でき、同じフレームで複数条件が成立した場合は上に表示したルールから採用する。

例として、固定位置の「開始」をタップし、最大8秒間「次へ」「再試行」を順に評価する。「次へ」なら `tap_image` を実行し、成功終了する。「再試行」なら別の手順へ進む。どちらも見つからなければ端末だけ失敗にして、最後に取得できた画像を診断用に残す。

## エクスポート

シナリオのJSONと参照画像をZIPにまとめる。インポート時は形式バージョン、ステップ構造、相対パス、画像形式、素材ハッシュ、展開サイズを検証する。保存時にホスト内のIDへ付け替える。端末のUDID、接続先、認証情報、実行履歴はパッケージに含めない。
