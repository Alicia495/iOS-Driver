# 画像認識設計

## 素材と認識処理

テンプレートはユーザーが静止画上で範囲を選び、ホストが元のスクリーンショットから切り出したPNGとする。探索範囲は画面全体の比率で保持し、指定がなければ全画像を探索する。アニメーション、時計、スクロールする文字など、変化しやすい部分は登録範囲から外せる。

1. 条件ステップに入った後の新規スクリーンショットを取得する。プレビュー用MJPEGの最後のフレームは判定に使わない。
2. 向きと画面プロファイルを確認し、探索範囲を画像上の矩形に変換する。端末差がある場合は、検証済みのサイズ範囲か条件に登録した画像バリエーションを使用する。
3. OpenCVの `matchTemplate` で照合する。初版の方式は `TM_CCOEFF_NORMED` とし、分散が極端に小さい素材は登録時にエラーにする。
4. 閾値以上の候補を重なりでまとめる。検出矩形、スコア、素材ID、フレームIDを返す。タップの対象を一意に決められない場合は複数候補として扱う。
5. 判定を再評価する場合は、新しい画像と残り時間を使う。初期設定としてポーリング間隔500ms、一致閾値0.85を調整の出発点とする。取得や処理の遅延がある場合、同じ端末に撮影を積み増さない。

初版の各条件は一致・不一致・複数候補・判定不能を区別する。画像の存在を見る分岐には複数候補でも一致を使用できる。位置を押す場合は一意に検出できるまで待つ。失敗時はその理由と最後の判定画像を保存できる。

## 検出位置のタップ

タップ用の条件評価では、操作直前に新しく画面を取得して位置を確認する。フレーム取得後に向き・画面領域が変わった場合や、アプリが検出結果を使うまでに許容時間を超えた場合は再判定する。検出矩形の中心または設定した矩形内の相対位置を論理座標へ変換する。指定した探索領域や有効表示範囲を外れる座標は拒否する。

## 調整とログ

調整画面で成功例と紛らわしい画像を比較し、検出枠と候補スコアを確認できるようにする。実行ログには素材、閾値、最高スコア、候補数、照合時間、分岐結果を残す。普段の判定で使った全画像の保存は行わず、診断画像は[運用設計](../operations/deployment.md)の保持ルールに従う。
